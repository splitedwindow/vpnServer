## Постановка проблеми та актуальність

В умовах масштабної міграції українців за кордон унаслідок повномасштабного вторгнення Російської Федерації мільйони громадян зіштовхнулися з проблемою захищеного підключення до вітчизняної мережевої інфраструктури. Банківські сервіси, державні портали та медіаплатформи часто недоступні з-за кордону через регіональні обмеження провайдерів. Наявні комерційні VPN-рішення орієнтовані переважно на анонімність і не забезпечують стабільного виходу саме через українську точку присутності.

## Об'єкт та предмет дослідження

**Об'єкт дослідження** — процес захищеної передачі мережевого трафіку між віддаленим користувачем і українською мережевою інфраструктурою.

**Предмет дослідження** — методи та засоби побудови програмно-апаратної VPN-системи з централізованою автентифікацією та шифруванням каналу зв'язку.

## Невирішене завдання

Наявні комерційні VPN-сервіси — NordVPN, Surfshark, Proton VPN, Mullvad — пропонують сотні серверів у десятках країн, проте не забезпечують гарантованого підключення саме через український IP. Рішення типу Outline VPN або Cloudflare WARP не мають вбудованої системи підписок і не інтегруються з централізованою RADIUS-автентифікацією. Жодне з розглянутих рішень не поєднує в єдиному сервісі: апаратний шлюз з українською точкою виходу, власний клієнтський застосунок, RADIUS-авторизацію за підпискою та керований вебінтерфейс. Саме ця ніша і є предметом розробки.

## Мета роботи

Розроблення програмно-апаратної VPN-системи на основі протоколу L2TP/IPsec і централізованої FreeRADIUS-автентифікації, що забезпечує захищений вихід через українську точку присутності з повним власним програмним стеком: вебсайтом, бекендом та клієнтським застосунком.

## Методи дослідження

У роботі використано:
- методи системного аналізу для проєктування багатокомпонентної архітектури;
- порівняльний аналіз VPN-протоколів (L2TP/IPsec, OpenVPN, WireGuard) для обґрунтування вибору;
- методи мережевого адміністрування для конфігурації MikroTik та FreeRADIUS;
- інженерні методи розроблення ПЗ при побудові бекенду (Node.js/Express), вебінтерфейсу (React) та клієнтського застосунку (Electron).

## Архітектура системи

Система складається з п'яти компонентів, що взаємодіють за схемою:

```
Користувач → Windows-клієнт (Electron) → VPN-шлюз MikroTik (L2TP/IPsec) 
→ FreeRADIUS → MySQL-база → Express REST API → платіжний сервіс
```

**Перший компонент** — вебсайт (React), що реалізує реєстрацію, вибір тарифу та завантаження клієнта.

**Другий компонент** — бекенд (Node.js/Express) із REST API для управління обліковими записами, генерації VPN-облікових даних і взаємодії з платіжними сервісами; дані зберігаються у MySQL.

**Третій компонент** — FreeRADIUS, що здійснює централізовану автентифікацію та авторизацію VPN-сесій на основі активних підписок. RADIUS відповідає виключно за перевірку облікових даних і авторизацію — не за шифрування трафіку.

**Четвертий компонент** — маршрутизатор MikroTik як апаратний VPN-шлюз: реалізує L2TP/IPsec (IPsec забезпечує шифрування тунелю методами AES/3DES з узгодженням ключів через IKEv1/PSK; MS-CHAPv2 — автентифікацію всередину тунелю) і делегує перевірку облікових даних RADIUS-серверу. MikroTik обрано завдяки нативній підтримці L2TP/IPsec, інтеграції з PPP AAA та RADIUS, доступності обладнання і широкій документації.

**П'ятий компонент** — Windows-клієнт (Electron): через PowerShell автоматично конфігурує системний L2TP/IPsec-профіль і встановлює з'єднання командою `rasdial` без ручного налаштування. Electron обрано за можливість виконання системних команд у привілейованому режимі при збереженні повноцінного графічного інтерфейсу.

## Безпекова модель

Конфіденційність забезпечується IPsec-шифруванням тунелю (AES-256/3DES); цілісність — HMAC-SHA. Потенційні ризики системи: компрометація Pre-Shared Key, відома вразливість MS-CHAPv2 до атак на NTLM-хеш у разі перехоплення трафіку до встановлення IPsec-тунелю, некоректне логування трафіку, несанкціонований доступ до MySQL з обліковими даними RADIUS. Для продуктивного розгортання передбачено зміну PSK, обмеження доступу до портів 1812/1813 лише з IP MikroTik і використання bcrypt для зберігання паролів у бекенді.

## Основні результати

Розроблено та протестовано прототип VPN-системи:
- успішність RADIUS-автентифікації — 98% (за результатами 50 тестових підключень із різними обліковими даними);
- середній час встановлення L2TP/IPsec-з'єднання — 5,2 с;
- підтверджено вихід через українську IP-адресу (перевірка через ipinfo.io та whoer.net);
- пропускна здатність VPN-тунелю — 100 Мбіт/с при тестовому навантаженні.

## Висновки

Розроблена VPN-система забезпечує захищений вихід через українську точку присутності шляхом поєднання апаратного шлюзу MikroTik (L2TP/IPsec), централізованої FreeRADIUS-автентифікації та власного програмного стеку. На відміну від комерційних аналогів, рішення орієнтоване на єдину українську точку виходу й інтегрує клієнтський застосунок, управління підписками та RADIUS-авторизацію в єдиний прототип сервісу. Подальший розвиток передбачає підтримку мобільних платформ, впровадження WireGuard як альтернативного протоколу з кращими характеристиками продуктивності та посилення захисту облікових даних.
